## The game
You start in the hub cave. Outside, five bases sit in a row in front of the cave mouth (the player owns the middle one, `BASES.home`); each has a mine cart on rails running north across the valley to a canyon spanned by a broken bridge. Hold E on the cart for 1 s (or press LAUNCH) to ride: W / GAS accelerates while fuel lasts, S / BRAKE brakes, Space / Shift / BOOST fires a booster. Run cash = `floor(distance / Distance Per Currency) * Currency * Currency Multiplier * multipliers` (`state.runPayout`; the three Cart Upgrades are bought at the base stall, `UPGRADES`; multipliers = extra carts, Golden Carts, rebirths, passes, wheel boost, event), banked when the cart stops, on RETURN, or after a crash (REVIVE costs Cash and puts you back at `CART.safeS` with a full tank). The goal: upgrade the cart (the Shop stall in the cave, restocks every 5 min; Cart Upgrades at the base stall; Starter Pack and OP V8 display pads at the base) until it is fast enough at the lip to clear the gap. Past the canyon the line runs on through the Great Arch (`TRACK.archS`) into the new areas (`ZONES`, built by `zones.js`), ending at Golden Station (`TRACK.length` = 3460 m): Bumpy Meadows (airtime humps), Crystal River (bridge over the water), Waterfall Gorge (the Sky Trestle climbs 34 m over a lake, then plunges through the waterfall), Glow Mine (one bore per track through the mountain) and Golden Sands (desert humps, the station's brakes stop the cart at the buffers and end the run). Each area shows a title card on entry; the first run that gets past the player's best into it pays its `bonus`. All prices are Cash (root CLAUDE.md rule: nothing is sold for premium currency).

Balance: `cartPhysics.js` is pure, so gear combos can be simulated in Node (import config.js + cartPhysics.js and step `stepCart`). Starting gear tops out ~280 m; Engine + Small Fuel ~430 m; V12 + Giant Fuel + Sport hits the far wall, add a Firework and it clears the canyon; 10 extra carts (the first rebirth needs 11 carts) drag that back into the wall; V16 reaches Bumpy Meadows, F140 Crystal River / the foot of the Sky Trestle, the 3-rebirth Cauldron tier Golden Sands, and the 4-rebirth Spirit tier and up make Golden Station. Past the far deck the profile is `TRACK.hills` (key points joined by smoothsteps); over a crest a fast cart leaves the rails (`hop` / `touchdown` events, rail drag in the air so hops are no speed trick); out of fuel and rolling back `CART.rollbackEnd` behind the best ends the run. Sim script pattern: step `stepCart` with full throttle per gear set and log `zoneAt(c.s)`. Engines show `speed` (accel = speed / 10).

Three.js (vanilla, no React) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; `main.js` awaits its init at top level, hence `build.target: 'es2022'`). Everything is procedural (canvas textures); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka (loaded in `index.html`).

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel). The game slug is the repo/folder name lowercased (`build-a-cart`); repo var/secret `LEGION_GAME_ID` is only an optional override; secret `LEGION_DEPLOY_TOKEN` is required.
- All tunables are in `src/config.js` (the rest of `src/` holds no theme values): identity, `SPAWN`, `MODES`, `PHYSICS`, the look (`RENDER`, `FOG`, `TIME_OF_DAY`, `LIGHT`, `GRAPHICS_PRESETS`, `BLOOM`, `NEON`), `TOUCH`, `CAMERA`, `SETTINGS`, the rig (`RIG*`, `PROPORTIONS`, `ANIM`), and the game: `VALLEY`, `CAVE`, `BASES`, `TRACK` (the shared rail height profile and the new areas' landmarks: river, gorge, falls, mine, station), `ZONES` / `zoneAt`, `CART` (ride physics), `RARITY` / `GEAR` / `DEFAULT_GEAR` / `INDEX_TABS` / `BUNDLES`, `ECONOMY`, `UPGRADES`, `REBIRTH`, `RESTOCK` / `INSTANT_MARKUP`, `PASSES`, `WHEEL`, `EVENTS`, `QUESTS` / `QUEST_STATS` / `QUEST_LEVELS` / `DICE`, `SAVE_SLOTS`, `SERVER_URL` / `NET`, `AUDIO`. The backend's quest pools (`QUEST_POOLS` in its constants.ts) must list the same quest ids as `QUESTS`.
- All Bloxity SDK calls go through `src/bloxity.js` and must never throw (SDK may be blocked). It handles init/loading steps, auth (user/guest), settings (`graphics_quality`, `camera_sensitivity`, `show_fps`, `fullscreen`), avatar + proportion change events, the portal `respawn_request` event, the avatar customizer, and the matchmaker helpers the future net layer needs (`resolveServerEndpoint`, `locateRoom`, `updateRoom`).

## Files (`src/`)
- `main.js`: boot order = Bloxity SDK -> renderer -> Rapier -> lighting, `createWorld` (valley), `buildTracks` (rails + bases), `buildCave` (hub), player body -> avatar (async) -> audio, fx, events, HUD, windows, ride, interact spots -> loop. The loop steps physics with the ride's slow-motion `timeScale`, pins the player into the cart seat while riding, feeds `cave.depth()` (0..1 how far inside) and the event weights into `lighting.setMods`, and refreshes signs/timers 4x a second. The loop body is `frame(forceDt)`; `__game.frame(1/60)` steps it by hand (the browser pane pauses rAF while hidden) and `__game.ride.warp(s, speed)` puts the riding cart anywhere on the line. `__game` (dev only) adds `ride`, `zones`, `state`, `S` (state.js), `events` (`events.force = 'storm'` forces an event), `fx`, `cave`, `tracks`, `teleport(x, y, z, facing)` (facing `Math.PI` = north, -Z).
- **Player**: `player.js` kinematic capsule + Rapier `KinematicCharacterController` (autostep, slopes, snap-to-ground, pushes dynamic bodies), own gravity/jump (coyote time + buffer). Feet position is `player.position`; `player.renderPosition` is interpolated for drawing. Falling below `PHYSICS.killY` respawns. `camera.js` third-person chase cam (boom, wheel zoom, wall clearance via `segmentClear`, speed FOV) and first person at the inner zoom end; `modes.js` `character` (avatar visible) / `player` (first person, avatar hidden), V toggles. `input.js` keyboard / mouse / pointer lock into `inputState`; `touch.js` + `touch.css` touch controls.
- `avatar/`: `character.js` (player.glb or procedural fallback), `loader.js` (Bloxity cosmetics + proportions from the CDN, `cdn.js`), `rig.js` + `animator.js` (procedural idle/run/airborne/landing; tunables in `ANIM`).
- **Physics**: `physics.js` Rapier world, fixed 60 Hz step with an accumulator; dynamic meshes bound via `bindMesh`/`addDynamic` are interpolated between ticks. Static geometry uses `addFixed` / `addFixedBoxFor`. `segmentClear` is the camera's ray against static colliders only.
- **World**: `world.js` the valley (studded grass split by the canyon, canyon walls + floor + blue crystal spikes, stepped cliffs with grass tops and blocky trees, the Great Arch, blocky clouds that grey in storms) and `zAt(s)` (track s -> world z). `track.js` rails + sleepers (instanced, all five tracks), the stepped dirt embankments (ramp and far landing deck, with colliders), broken-bridge pieces, buffer stops, ridges + plank bridges between bases, the base stalls / +1 Cart pads, the home base's Starter Pack and OP V8 display pads and the canvas signs (`setCartBar`, `setOwner`); `canvasSprite` / `fmt` helpers. `cave.js` the hub room + mountain (navy studded walls, moss, crystals, cobwebs, dynamite, fences), the Shop stall, Sell Gear / Index / Daily Gift pads, the Lucky Wheel (`wheelDisk`), the two record boards, its point lights; `outside.js` the long cliff wall across the back (stepped tiers, grass ledges, trees, red crystals) with a cave mouth behind every base (only the home one leads into the hub), the base plateaus (y = 0, jagged stone edges, narrowing to a tongue round the rails), the light-green ramps down to the valley floor (y = -`TRACK.valleyDrop`) and the plank bridges between plateaus. `zones.js` the areas past the arch (meadow flowers + hay bales, the river with white stone banks/bluffs/pools, the gorge walls + lake + two scrolling waterfall sheets + foam + rainbow, the Glow Mine mountain with lined bores, timber frames, neon crystals and lanterns, the desert with mesas/cacti and Golden Station's platforms and finish arch; `grassyAt` / `cliffColors` steer world.js's trees and cliff colours; `indoorAt` / `waterAt` feed the light and the water sounds). `track.js` also builds the new supports: stepped dirt/sand/rock mounds under humps and timber trestles (river bridge, Sky Trestle). `world.js` builds relative to the valley floor (its root sits at `VALLEY_Y`); use `trackHeight` / `LIP_Y` / `LAND_Y` / `FLOOR_Y` from cartPhysics.js for absolute heights; `studs.js` the stud texture + world-scaled box UVs (`studBox`, `studMat`, `studPlane`), `build.js` `block`/`pillar` helpers.
- **Game**: `cartPhysics.js` (pure: `trackHeight`, `trackSlope`, `cartStats`, `newCart`, `stepCart`, `fireBoost`), `cartModel.js` (cart, wagons, engines, tanks, wheels, boosters; exhaust/flame tips in `userData`), `ride.js` (mount, fixed-rate cart sim, wagons following breadcrumbs of the lead cart's path, effects, crash/revive/return, slow motion over the gap and big airs, zone cards + first-visit bonuses, the waterfall splash-through, the mine's darkness (`ride.tunnel`), ambient area particles spawned ahead of the cart so they stream past like wind; - **Sky and light**: `lighting.js` sky shader, stars, PMREM environment, shadowed sun following the player, fog, day/night blend (N), plus `setMods(storm, gold, indoor)` (storm clouds, gold-rush warmth, darker sun + teal fill inside the cave) and `flash()` (lightning). `postfx.js` bloom (EffectComposer: HDR half-float render -> UnrealBloomPass -> radial speed blur `setBlur` -> OutputPass), on for the High/Ultra presets only (`BLOOM`; threshold 2.0 so sunlit surfaces never bloom).

- Controls: WASD/arrows walk (W/S gas and brake while riding), Shift sprint (boost while riding), Space jump (boost while riding), E hold to interact / ride, 1 or B backpack, mouse look (click grabs the cursor = pointer lock, Esc releases it, then Esc opens the portal menu), wheel zoom, V mode, N day/night, R back to the cave. ## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
